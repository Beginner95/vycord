# Список участников сервера (online/offline)

**Дата:** 2026-07-30
**Область:** только клиент (`client/src/components/UserList.tsx`, `UserList.css`). Бэкенд не меняется.

## Проблема

Правая панель (`UserList`) сейчас показывает глобальный список ВСЕХ онлайн-пользователей системы — не привязанный к текущему серверу. По нему невозможно понять, кто вообще состоит в открытом сервере: список смешивает участников разных серверов и не показывает офлайн-участников вовсе.

## Цель

Правая панель показывает участников **текущего сервера**, разбитых на две группы — «Online» и «Offline» — вместо глобального списка всех онлайн в системе.

## Источники данных (уже существуют, ничего нового заводить не нужно)

- `serverStore.members: MemberWithUser[]` — участники текущего сервера (`user_id`, `username`, `avatar_url`, `role`, `joined_at`). Уже загружается через `GET /api/v1/servers/{id}/members` при каждом выборе/переключении сервера в `AppPage.tsx` (`loadServerMembers`); при смене сервера сбрасывается в `[]` до завершения загрузки.
- Глобальный набор «кто сейчас онлайн» — `UserList.tsx` уже получает его через `apiService.getOnlineUsers()` при монтировании и обновляет по WS-событиям `online_users` / `user_joined` / `user_left` / `user_updated`.

Список участников сервера = пересечение этих двух источников по `user_id`.

## Изменения в `UserList.tsx`

1. Подключить `useServerStore()` → `currentServer`, `members`.
2. Оставить существующий эффект подписки на онлайн-события, но хранить в стейте не `User[]`, а `Set<string>` id-шников (`onlineIds`) — данные о username/avatar теперь берутся из `members`, а не из ответа `getOnlineUsers()`.
3. `useMemo`: разбить `members` на `onlineMembers` (`onlineIds.has(m.user_id)`) и `offlineMembers` (остальные), внутри каждой группы сортировать по `username.localeCompare(other.username, undefined, { sensitivity: 'base' })`.
4. Рендер: два блока-категории — `Online — {onlineMembers.length}` и `Offline — {offlineMembers.length}`. Оба всегда рендерятся, даже при 0 (единообразно с текущим поведением, без отдельного loading-состояния — пустые группы во время короткой загрузки участников при переключении сервера).
5. Кнопка звонка (📞) — только у участников из `onlineMembers`, кроме самого себя (то же условие, что и сейчас: `currentUser && u.user_id !== currentUser.id`). У `offlineMembers` кнопки нет.
6. Мобильная версия не меняется структурно — `data-mobile-panel="members"` по-прежнему показывает `.user-list`.

## Что сознательно не делаем (вне скоупа)

- **Роли/бейджи** (владелец/админ) — по решению пользователя, простой список без ролей.
- **Живое обновление членства сервера.** Если во время открытой панели кто-то присоединяется к серверу или покидает его, список не обновится сам — обновление произойдёт только при следующем переключении сервера (перезагрузке `members`). Причина: WS-событий `server_member_join`/`server_member_leave` в протоколе ещё нет (отдельный пункт на борде). Это ограничение уже присутствует в существующем коде (та же `members`-стора используется в `ChannelSidebar` для резолва имён и тоже не обновляется в реальном времени) — новых багов не вносим, просто наследуем существующее поведение.
- **idle/dnd-статусы.** `User.status` в типах поддерживает `idle`/`dnd`, но нигде в приложении реально не устанавливается и не отображается. Оставляем бинарную модель online/offline, как явно попросили в задаче.
- **Звонок офлайн-участнику.** Кнопка звонка просто не рендерится для офлайн — не пытаемся звонить/будить недоступного пользователя.

## Проверка

В проекте нет юнит-тестов на клиенте (нет vitest/config). Проверка — вручную: запустить dev-сервер, зайти двумя пользователями в один сервер, убедиться, что оба видят корректное разбиение на Online/Offline, и что переключение статуса (выход/вход одного из них) обновляет группы в реальном времени у другого. Дополнительно проверить, что `ChannelSidebar` (резолв имён для voice-участников через `members`) продолжает работать без регрессий — эта функциональность не меняется, но зависит от того же источника данных.
