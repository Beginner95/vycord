# Звонки 1:1 через SFU (VYC-103) — дизайн

Дата: 2026-10-03 · Ветка: `VYC-103-refactoring-p2p`

## Цель

Оживить личные звонки 1:1. Сейчас они реализованы как P2P (`services/call.ts`,
`CallUI.tsx`, ретрансляция `webrtc_*` через хаб) и не работают. Звонить можно
из двух мест: из списка друзей и из списка участников сервера — онлайн-пользователю,
по наведению на строку.

Критерий успеха: звонок надёжно соединяется (в том числе через NAT/TURN), обе
стороны видят понятные состояния — «звоним», «входящий», «идёт»,
«завершён / отклонён / не отвечает», пропущенный звонок не теряется.

### Почему старый P2P не работал (по чтению кода, не воспроизводилось)

1. Вызываемый до «Принять» выбрасывает все ICE-кандидаты звонящего
   (`addIceCandidate` только при `remoteDescription`, буфера нет).
2. `call_started` приходит звонящему сразу после `call_start` — `CallUI`
   открывает «идёт звонок», когда никто не ответил.
3. `calls` чистится только на WS-коннекте; зависшая запись → «already in a call».
4. `disconnected` сразу завершает звонок — ни ICE restart, ни реконнекта.
5. Нет проверки дружбы/блокировки; в модалке нет имени звонящего.

## Принятые решения

| # | Вопрос | Решение |
|---|---|---|
| 1 | Транспорт | **Звонок 1:1 — приватная комната SFU**, `room_id = call_id`. Весь медиа-стек групповых звонков (экран, реконнект, ICE restart, качество, NC, фоны) переиспользуется. Старый P2P удаляется. |
| 2 | Кто кому может звонить | **Как ЛС — `CanDM`**: блокировка запрещает всегда, друзьям можно всегда, остальным — по `allow_dm_from` получателя. Новой настройки нет. |
| 3 | Где идёт звонок | **В основной колонке через `CallStage`**, как у групповых; при навигации звонок живёт в `CallDock`. |
| 4 | Входящий | **Карточка `IncomingCallCard` без затемнения**: аватар, имя, «Принять»/«Отклонить», рингтон. |
| 5 | Если кто-то уже в звонке | **Проходит, принятие переключает**: «Принять» / «Позвонить» выводит из текущего звонка (канального или 1:1). |
| 6 | Таймаут и пропущенные | **Серверный таймаут 45 с** → `missed`; у получателя тост «Пропущенный звонок» с «Перезвонить»; записи `calls` сохраняются для будущих событий в личках. |
| 7 | Платформы | **Десктоп (вкл. Electron) и мобильный сразу.** |
| 8 | Когда звонок окончен | **Ушёл один — конец у обоих.** Обрыв сети покрывается grace. |
| 9 | Владелец жизненного цикла | **API.** SFU о звонках 1:1 ничего не знает и не меняется; обратного канала SFU→API нет. |
| 10 | Иконка у не-друзей в `UserList` | Видна у онлайн-участников; запрет проверяет сервер, клиент показывает тост. Флаг `can_call` в списке участников не вводим. |

## 1. Сервер

### Данные — миграция `028_direct_calls`

Таблица `calls` (миграция 006) остаётся. Миграция закрывает висящие
`ringing/active` и добавляет `accepted_at TIMESTAMPTZ NULL`. Уникальных
индексов нет — см. «Поправки при планировании», п. 1.

Статусы прежние: `ringing → active → ended`, `ringing → rejected | missed`.
Отмена звонящим во время дозвона — тоже `missed` (для получателя это
пропущенный звонок).

### `CallUseCase` — машина состояний (переписывается)

Единственное место с правилами звонка. Зависимости: `CallRepository`,
проверка `CanDM` (`friendUseCase`), «онлайн ли пользователь» (хаб),
отправка событий (интерфейс-нотификатор поверх хаба), часы (инъекция, для тестов).

- `Start(caller, receiver)`:
  1. `CanDM(caller, receiver)`; ошибка → `forbidden` (звонок себе тоже
     `forbidden` — `canInteract` уже отвергает).
  2. Получатель офлайн → `offline`.
  3. Есть `ringing`-звонок receiver→caller (встречный вызов) → **принять его**
     (`Accept`), нового не создавать.
  4. Есть живой звонок caller↔receiver → вернуть его (идемпотентность).
  5. У звонящего другой живой звонок → завершить его (`ended`, решение 5).
  6. Создать `ringing`, запустить таймер дозвона 45 с, разослать `call_ringing`.
- `Accept(user, callID)`: user — получатель, статус `ringing`. Живой звонок
  получателя с кем-то другим завершается. `active`, `accepted_at = now`,
  таймер дозвона снимается, `call_accepted` обоим.
- `Reject(user, callID)`: получатель, `ringing` → `rejected`, `call_ended {reason: rejected}`.
- `End(user, callID, reason)`: участник. `ringing` (отмена звонящим) → `missed`;
  `active` → `ended`. `reason` из клиента принимается только `ended | failed`.
- Таймер дозвона истёк → `missed`, `call_ended {reason: timeout}` обоим.
- `OnDisconnect(user)`: у пользователя живой звонок →
  `ringing` завершается сразу (`missed`), `active` — запускается grace 20 с.
- `OnConnect(user)`: снимает grace-таймер, шлёт клиенту `call_state`
  (снимок живого звонка или `null`).
- Grace истёк → `ended`, `call_ended {reason: ended}` второму.
- При старте API: все `ringing/active` в БД закрываются (`missed`/`ended`) —
  таймеры живут в памяти и рестарт не переживают.

Все переходы — условный `UPDATE … WHERE status = <ожидаемый>`: проигравший гонку
получает `invalid_state`, а не двойной переход.

`EndAllActiveCalls` на WS-коннекте (`websocket.go:104`) **удаляется** — сейчас он
убил бы звонок при любом реконнекте; его роль берут `OnConnect` + очистка при старте.

API работает в одном экземпляре (хаб и так в памяти) — таймеры в памяти этим
допущением и ограничены.

### WS-протокол

Сервер шлёт события **обоим** участникам; у каждого — `call_id`.

| Клиент → сервер | Сервер → клиенты |
|---|---|
| `call_start {receiver_id}` | `call_ringing {call_id, caller, receiver}` |
| `call_accept {call_id}` | `call_accepted {call_id}` |
| `call_reject {call_id}` | `call_ended {call_id, reason: "rejected"}` |
| `call_end {call_id, reason?: "ended"\|"failed"}` | `call_ended {call_id, reason: "ended"\|"missed"\|"timeout"\|"failed"}` |
| — (на (ре)коннекте WS) | `call_state {call: {call_id, status, caller, receiver} \| null}` |
| — (отказ) | `call_error {code: "forbidden"\|"offline"\|"not_found"\|"invalid_state", call_id?}` |

`caller` / `receiver` — `{id, username, avatar_url}`, отдельный запрос клиенту
не нужен. Отказы идут собственным типом `call_error`, не общим `error`.

**Удаляются:** обработчики `webrtc_offer/answer/ice_candidate`, события
`incoming_call`, `call_started`, `call_accepted` старого формата, `call_rejected`.
Неизвестные типы от старых клиентов уже логируются warn в `default`.

### Токен в комнату

`POST /api/v1/calls/{id}/voice-token` — тот же `authtoken.GenerateRoomToken`,
`room_id = call_id`. Выдаётся только участнику звонка и только в статусе
`active`; иначе 403/404 через `httperr`. SFU не меняется — он и так принимает
комнату с любым UUID по room-токену (как гостевые ссылки).

## 2. Клиент — состояние и сервисы

### `directCallStore` (новый, Zustand)

Единственный подписчик на `call_*`.

- `phase`: `idle | outgoing {callId, peer} | incoming {callId, peer, wouldSwitch} | connecting | active {callId, peer} | ending {reason}`.
  `ending` — короткий показ исхода («Отклонён» / «Не отвечает» / «Не удалось
  соединиться») перед `idle`.
- `missed: Array<{callId, peer, at}>` — в памяти, для тостов.
- `viewOpen: boolean` — открыт ли экран звонка в основной колонке.
- Действия: `call(userId)`, `accept()`, `reject()`, `hangup()` (это же отмена
  при дозвоне), `dismissMissed(callId)`, `openView()`, `closeView()`.
- `call_state` после реконнекта WS восстанавливает фазу из снимка сервера.
- `wouldSwitch` = на момент входящего клиент уже в звонке (`callStore.status !== 'idle'`).

### Медиа: `groupCallService` + `callStore`, обобщённые до «комнаты»

- `JoinCallOptions.kind: 'channel' | 'direct'`. Для `direct`: `roomId = callId`,
  вместо имени канала/сервера — `peer`.
- Для `direct` **не отправляются** `voice_joined / voice_left / voice_call_ring /
  voice_call_cancel` — 1:1 не попадает в голосовое присутствие каналов.
  `mic_muted / camera_* / screen_share_* / connection_quality` идут как есть
  (хаб рассылает их по `user_id`).
- `CallCredentials.getVoiceToken` выбирает эндпоинт по `kind`. Гостевые учётные
  данные не трогаются (гость в 1:1 не участвует).
- `callChannelId` → `callRoomId` + `callKind` (+ `callPeer` для `direct`).
  Переименование — чтобы компилятор нашёл каждого читателя (`DesktopShell`,
  `CallDock`, `UpdateBanner`, `useVoiceRecording`, `announceCameraState`,
  мобильный шелл и др.).

### Связка жизненного цикла

- `call_accepted` → если клиент в другом звонке, `callStore.leave()`; затем
  `callStore.join({kind: 'direct', roomId: callId, peer})`; фаза `connecting → active`.
- `call_ended` → `callStore.leave()` (если в этой комнате), сигнал завершения, `ending → idle`.
- Клиент шлёт `call_end {reason: "failed"}`, если реконнект `groupCallService`
  окончательно не удался или если собеседник получил `participant_left` в SFU и
  не вернулся за 15 с (grace SFU).
- «Завершить» в `CallStage` / `CallDock` для `direct` → `directCallStore.hangup()`,
  не голый `leave()`.

### Удаляется

`services/call.ts` и его тесты, `components/CallUI.tsx`, `CallUI.css` и тесты,
рассылка `discrod:*` `CustomEvent` в `websocket.ts` (единственный потребитель —
`CallUI`), `UserList.handleCallUser` на старом сервисе, `<CallUI />` в
`DesktopShell` и `MobileShell`. Логика камеры/фона из `call.ts` (VYC-100) уже
есть в групповом стеке — перед удалением сверить, что ничего уникального не теряется.

## 3. UI

### Точки входа

- **`FriendRow` (десктоп):** у онлайн-друга при наведении и при фокусе с
  клавиатуры справа (рядом с «⋮») кнопка «Позвонить». У офлайн — нет.
- **`UserList`:** существующая hover-иконка → `directCallStore.call()`. Только
  онлайн-участники, не сам пользователь. На `call_error forbidden` — тост
  «Пользователь принимает звонки только от друзей».
- **Мобильный:** пункты «Позвонить» в `FriendsScreen` / `useFriendMenuItems` и
  `ChannelInfoScreen` → `directCallStore.call()`.

Если звонящий уже в звонке — у кнопки тултип «Завершит текущий звонок».

### Исходящий

`viewOpen = true`: основная колонка показывает экран дозвона — аватар
собеседника с пульсацией, «Звоним…», «Отменить», гудки. `CallDock`:
«Звоним {имя}». `call_accepted` → на том же месте `CallStage`. Исход
`rejected / timeout / failed` — короткий статус с сигналом, затем закрытие.

### Экран звонка 1:1

`CallStage` на всю высоту основной колонки (чата под ним нет — личек ещё нет),
заголовок — аватар и имя собеседника вместо `#канала`. Демонстрация экрана,
качество, громкость, фоны — как в групповых. Выбор канала / сервера / «Дома»
закрывает экран (`closeView`), звонок продолжается в `CallDock`
(«В звонке с {имя}»); клик по доку — `openView`. На мобильном — существующий
`MobileCallScreen` с тем же обобщением (заголовок — собеседник, «Завершить» → `hangup()`).

### Входящий — `IncomingCallCard`

Портал вверху по центру, без затемнения, приложение под ним кликабельно:
аватар, имя, «Звонит вам…», «Принять» (зелёная) / «Отклонить» (красная),
рингтон. При `wouldSwitch` — подпись «Принятие завершит текущий звонок» и
рингтон тише. Electron при неактивном окне — системное уведомление + подсветка
окна в панели задач. Мобильный — полноширинная плашка сверху.

### Пропущенный — `MissedCallToast`

Стопка внизу справа (мобильный — сверху): «Пропущенный звонок от {имя}»,
«Перезвонить», ✕. Живёт до закрытия. Electron при неактивном окне —
дополнительно системное уведомление.

### Звуки

Гудки исходящего (новый), рингтон входящего — генератор из `useCallRing`
выносится в `audioService` и используется обоими местами; «отклонён/занят» и
«завершён» — существующие.

Всё — на токенах дизайн-системы (`client/docs/`), строки ru/en через i18n.

## 4. Ошибки и граничные случаи

| Ситуация | Поведение |
|---|---|
| Получатель офлайн / ушёл офлайн при дозвоне | `call_error offline` / `call_ended {reason: missed}` |
| `CanDM` запрещает | `call_error forbidden` → тост |
| Встречные A→B и B→A | второй `call_start` принимает первый звонок |
| Двойное «Позвонить» / «Принять» | идемпотентно |
| `Accept` после таймаута / отмены | `call_error invalid_state`, карточка закрывается |
| Обрыв WS с API в активном звонке | grace 20 с; вернулся → `call_state`, звонок жив; нет → `ended` у второго |
| Медиа не поднялось (токен / SFU / ICE) | клиент → `call_end {reason: failed}`, оба видят «Не удалось соединиться» |
| Рестарт API | висящие звонки закрыты при старте; клиенты по `call_state null` сбрасывают UI |
| Звонок себе | `forbidden` |

**Совместимость версий.** Старые клиенты шлют `call_start` + `webrtc_*`; новый
сервер `webrtc_*` игнорирует, старый клиент не понимает `call_ringing` — вызов
не проходит, как и сейчас (не регрессия). Режима совместимости нет: клиенты
обновятся автообновлением.

## Поправки при планировании (2026-10-03)

Найдены при чтении кода во время составления плана
(`docs/superpowers/plans/2026-10-03-direct-calls.md`); имеют приоритет над
разделами выше.

1. **Уникальных индексов нет** (раздел 1, «Данные»). Индекс «один живой
   звонок на получателя» противоречит решению 5: занятый активным звонком
   обязан получить `ringing`. Конкурентность закрывает `sync.Mutex` в
   `CallUseCase` (API — один процесс) + условные переходы. Новое правило:
   если у получателя **уже звонит** другой вызов — `call_error busy`
   (тост «Пользователь сейчас занят»). Миграция 028 лишь закрывает висящие
   звонки и добавляет `accepted_at`.
2. **`callChannelId` не переименовывается** (раздел 2). Он остаётся «канал
   звонка» (у 1:1 — `null`); добавляются `callKind`, `callRoomId`,
   `callPeer`, `lastExit`. Проверки «в звонке вообще» переводятся на
   `callRoomId`. Переименование задело бы ~20 файлов и 17 тестов без пользы.
   `callStore.join` в другую комнату сначала делает `leave()` текущей —
   это реализует «переключение» и для входа в голосовой канал из звонка 1:1.
3. **Фильтр комнат в presence-воркере.** Воркер считает каждую комнату SFU
   голосовым каналом; без фильтра комната 1:1 попала бы в голосовое
   присутствие и в «события звонка» чата. `Worker.SetRoomFilter(callUseCase.IsCallRoom)`.
4. **`call_state` пишется прямо в `client.Send`**, а не через хаб:
   регистрация в хабе асинхронна.
5. **Рингтон** — существующий `audioService.startRingtone()` (с тихим
   режимом), а не генератор из `useCallRing`; гудки исходящего —
   новый `audioService.startRingback()`.
6. **Токен комнаты** выдаёт `CallUseCase.IssueRoomToken` (HTTP —
   `CallHandler`), `VoiceTokenUseCase` не трогается.
7. Вероятная главная причина «звонок не проходит» в старом коде:
   `callRepository` сравнивал `err == sql.ErrNoRows`, а pgx возвращает
   `pgx.ErrNoRows` — `GetActiveByUser` без звонка отдавал ошибку и
   `StartCall` падал всегда. Репозиторий переписывается.

## Поправки при реализации (2026-10-03)

Расхождения реализации с разделами выше и с «Поправками при планировании»:

1. **Порт presence называется `DirectCallPresence`**: имя `CallPresence`
   уже занято портом гостевых звонков.
2. **`call_state` ставится в `client.Send` ДО регистрации клиента в хабе**
   (уточнение п. 4 выше). Иначе при вытеснении дублирующей сессии есть окно,
   в котором закрытие канала старой сессии приводит к панике.
3. **Сбой таймера дозвона** (ring-timeout) логируется и повторяется каждые
   `CallRingRetryDelay` (5 с), а не теряется.
4. **Клиент возвращает фоновый звонок X**, если входящий Y отклонён или
   пропущен (фаза снова `active` для X), и **молча выходит из комнаты X** по
   `call_ended` для X, когда текущая фаза принадлежит другому звонку.
5. **Фаза `connecting`** показывает экран «Соединение…», пока не поднята
   комната SFU.
6. **Экран звонка закрывается только навигацией пользователя**; смена фазы
   сама экран не закрывает.
7. **Мобильный клиент:** на экране дозвона есть кнопка «свернуть»; экран
   звонка 1:1 снимается со стека, когда пользователь входит в канальный звонок.
