# Форматирование текстового сообщения (B/I/U, ссылки, списки, цитата)

**Дата:** 2026-08-08
**Область:** клиент (`client/src/components/ChatArea.tsx`, `ChatArea.css`, новый `utils/markdown.ts`, `electron/main.ts`, i18n). Подход A — Markdown-разметка (как в Discord), сообщения остаются в виде plain-text строки.

## Проблема

Панель инструментов над полем ввода сообщения (`ChatArea.css:301`) содержит только одну кнопку «Цитата» с текстом. Нет возможности оформить сообщение: жирный, курсив, подчёркнутый, вставить ссылку, нумерованный/маркированный список. Сообщения хранятся и отправляются как plain-текстовая строка (`createMessage(channel.id, input.trim())`).

## Цель

Расширить панель инструментов набора сообщения: убрать слово «Цитата» (оставить только иконку), добавить кнопки **B / I / U**, кнопку вставки ссылки, кнопку нумерованного и маркированного списка. Разметка представлена Markdown-синтаксисом (как Discord). Готовые сообщения рендерятся с форматированием и кликабельными ссылками (открываются в системном браузере в Electron, новой вкладке — в вебе). То же доступно при редактировании сообщения.

## Что сознательно не делаем (вне скоупа)

- **Не используем WYSIWYG/contenteditable.** Поле остаётся `<textarea>`; разметка видна как введённые символы (UX Discord). Это сохраняет работу существующей `useMentionAutocomplete`, которая читает `textarea.value`.
- **Без сторонних Markdown-библиотек** (`marked` и т.п.) — не нужны зависимости и слой санитизации.
- **Вложенные блоки** (цитата внутри списка, список внутри цитаты и т.п.) — вне скоупа (только плоская вложенность инлайна внутрь строки).
- **Другие Markdown-фичи** — нет зачёркивания, кода, заголовков, таблиц. Только указанный набор токенов.

## Решение

### Хранение

Сообщения по-прежнему отсылаются и хранятся как plain-text строка с Markdown-маркерами. Изменений схемы БД и сервера нет.

### Рендеринг — новый модуль `utils/markdown.ts`

Заменяет поэлементный разбор `renderMessageBody` (ChatArea.tsx:102) на парсер, возвращающий React-узлы. Без `dangerouslySetInnerHTML` — только React-элементы.

Инлайн-токены внутри строки:
- `**жирный**` → `<strong>`
- `*курсив*` → `<em>`
- `__подчёркнутый__` → `<u>`
- `[текст](url)` → `<a href target="_blank" rel="noopener noreferrer">`
- голый `http://`, `https://`, `www.` → авто-ссылка (`<a>`)

Блочный уровень (по строкам, сохраняя текущую логику групп ChatArea.tsx:102-124):
- `> ` → цитата (класс `message-quote`)
- `1. ` → `<ol><li>`
- `- ` / `* ` → `<ul><li>`

`@mentions` применяются к тексту после снятия инлайн-разметки через существующий `tokenizeMentions`.

Безопасность ссылок: протокол фильтруется — только `http:`, `https:`, `mailto:`. `[text](javascript:...)` и аналоги рендерятся обычным текстом. Незакрытая разметка (`**bold` без `**`) не превращается в форматирование.

### Панель инструментов `chat-input-toolbar`

Ряд иконок вместо одной кнопки:

| Кнопка | Действие |
|--------|----------|
| Цитата (только иконка) | префикс `> ` / снятие |
| **B** | обернуть `**…**` / снять |
| **I** | обернуть `*…*` / снять |
| **U** | обернуть `__…__` / снять |
| Ссылка 🔗 | диалог «Текст + URL» → `[текст](url)` |
| Нумерованный список | префикс `1. ` по строкам |
| Маркированный список | префикс `- ` по строкам |

Тумблер-логика как в `toggleQuotePrefix` (ChatArea.tsx:353): если выделение уже обёрнуто — снять, иначе добавить; каретка выставляется через существующую логику `shiftFor`. Активное состояние кнопки — по позиции каретки (как сейчас у цитаты через `caretInQuoteLine`).

`FloatingQuoteButton` (выделение текста в чате/поле) тоже показывает только иконку без слова.

### Диалог ссылки

Кнопка «Ссылка» открывает небольшой инлайн-попап с полями «Текст ссылки» и «URL»:
- Если «Текст» пуст, а URL задан → `[url](url)`.
- Если URL пуст → приём блокируется (валидация + подсветка).
- Вставка `[текст](url)` в позицию каретки/вместо выделения.

### Вставка из буфера (Ctrl+V)

Обработчик `onPaste` на textarea:
- Чтение буфера через `navigator.clipboard.readText()`, фолбэк `e.clipboardData.getData('text/plain')`.
- Если в буфере валидный одиночный URL **и** в поле непустое выделение (`selectionStart !== selectionEnd`) → заменить выделение на `[выделенныйТекст](clipboardURL)`.
- Если URL в буфере без выделения → обычная вставка текста (попадает под авто-ссылки при показе).

### Открытие ссылок

**Electron (`electron/main.ts`).** Сейчас `setWindowOpenHandler` отсутствует. Добавить:
- `setWindowOpenHandler`: перехватывает `window.open` и `<a target="_blank">` → возврат `{ action: 'deny' }` + `shell.openExternal(url)`.
- `will-navigate`: для клика по `<a>` без target, если внешняя ссылка → `event.preventDefault()` + `shell.openExternal(url)`, чтобы клик не уводил SPA.

**Веб.** Ссылки рендерятся как `<a target="_blank" rel="noopener noreferrer">` — новая вкладка браузера.

### Редактирование сообщений

Тот же набор кнопок панели добавляется в `message-edit-input` (ChatArea.tsx:639), переиспользуя общую логику тумблеров/пасте. Рендеринг форматирования работает для всех сообщений (новых и отредактированных), т.к. `renderMessageBody` рендерит все сообщения.

## i18n

- Удалить текстовое использование `chat.quote` в кнопке (остаётся только иконка; `chat.quote` можно оставить только для `aria-label`/`title`).
- В `ru.ts`/`en.ts` добавить ключи для доступности (aria-label) новых кнопок: жирный, курсив, подчёркнутый, ссылка, нумерованный список, маркированный список, и для диалога ссылки («Текст ссылки», «URL», кнопка «Вставить»/«Отмена»).

## Проверка

- Модульные тесты `utils/markdown.ts` (парсер): жирный/курсив/подчёркнутый, `[текст](url)`, авто-ссылки, цитаты, списки, защита от `javascript:`, незакрытая разметка.
- e2e (`client/e2e/`): ввод `**жирный**`, `1. item`, `- item` → проверка результирующих DOM-узлов (`strong`, `ol/li`, `ul/li`, клик по `a`).
- `npm run check:i18n` для согласованности ключей.
- Ручная проверка в Electron: клик по ссылке открывает системный браузер, окно приложения не уводит от SPA.
