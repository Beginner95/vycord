# Статус микрофона и индикация говорящего на плитках собеседников

**Задача:** На плитке каждого собеседника в звонке (групповом и 1-на-1) показывать, замьючен ли у него микрофон, и подсвечивать плитку, когда он говорит — чтобы быстро понять, кто активен в разговоре из нескольких участников.

**Дата:** 2026-07-18
**Ветка:** `VYC-34-show-users-counts` (продолжение текущей ветки; либо новая `VYC-XX-mic-status` — уточняется на этапе плана)

## Проблема

Сейчас статус микрофона и индикация активности голоса видны **только для своей** плитки (`useMicLevel` хук + `.video-tile.speaking` рамка + мигающая `mic-dot` в лейбле, в `GroupCallUI.tsx`/`CallUI.tsx`). У плиток собеседников нет ни того, ни другого: непонятно, кто из нескольких участников сейчас говорит, и замьючен ли у кого-то микрофон.

Похожая работа уже проектировалась в ветке `VYC-21-show-microphone-users-in-card`, но она не смержена в `main` и содержит вперемешку не относящиеся к этой задаче правки (шаринг экрана, панель настроек, навигация). Архитектура ниже спроектирована заново под текущее состояние `main`, переиспользуя проверенную часть идеи (WS broadcast для мьюта, VAD для говорения), но без остального.

## Решение

Два независимых механизма, аналогичных существующим в проекте паттернам:

1. **Мьют-статус** — WS-событие `mic_muted`/`mic_unmuted`, зеркалирующее уже существующий `screen_share_started`/`screen_share_stopped` (тот же хаб, тот же стиль broadcast всем клиентам).
2. **Индикация говорящего** — чисто клиентский VAD, переиспользующий уже существующий в коде хук `useMicLevel` (AudioContext + AnalyserNode, порог `level > 0.05`), применённый к `remoteStream` каждого участника вместо только своего.

Визуально — единый компонент-бейдж (кружок в углу плитки, 3 состояния), одинаковый для своей и чужих плиток.

### Поток данных — мьют-статус

```
Клиент A: вход в звонок (после handleJoinGroupCall/joinGroupCall)
  → WS "mic_muted" | "mic_unmuted" {} (текущее состояние)
  → Hub.BroadcastMessage {type, payload: {user_id: A}} всем клиентам

Клиент A: переключение мьюта (handleToggleMute)
  → WS "mic_muted" | "mic_unmuted" {}
  → Hub.BroadcastMessage {type, payload: {user_id: A}} всем клиентам

Клиент B (уже в звонке): видит A в onPeerJoined
  → повторно отправляет СВОЁ текущее состояние (mic_muted|mic_unmuted)
  → это гарантирует, что A (только что зашедший) узнает статус уже бывших в звонке участников
```

`onPeerJoined` в `groupCall.ts` срабатывает в двух случаях: когда я обнаруживаю уже присутствующих участников при своём входе, и когда кто-то новый заходит после меня. В обоих случаях повторная отправка своего состояния безопасна и идемпотентна — лишний broadcast не создаёт видимых проблем, а закрывает окно, когда новый участник не знает статус остальных.

Реконнект отдельно не обрабатывается: когда клиент переподключается к SFU, для остальных участников это выглядит как повторный join → у них сработает `onPeerJoined` → они по правилу выше перешлют своё состояние → переподключившийся клиент получит его через общий broadcast.

### Сервер — `server/internal/delivery/http/handler/websocket.go`

Новые кейсы в `handleMessage`, по образцу `handleScreenShareStarted`/`handleScreenShareStopped`:

```go
case "mic_muted":
    h.handleMicMuted(client)
case "mic_unmuted":
    h.handleMicUnmuted(client)
```

```go
func (h *WebSocketHandler) handleMicMuted(client *ws.Client) {
    h.hub.BroadcastMessage(&ws.Message{
        Type:    "mic_muted",
        Payload: mustMarshal(map[string]interface{}{"user_id": client.UserID.String()}),
    })
}
// handleMicUnmuted — симметрично, type: "mic_unmuted"
```

Без нового состояния в `Hub` — событие транзитное, как `screen_share_*`.

### Клиент — точки отправки (`GroupCallUI.tsx`, `CallUI.tsx`)

- После успешного входа в звонок (там же, где сейчас выставляется `isMicAvailable`/`isMuted`) → отправить текущее состояние
- `handleToggleMute` → отправить новое состояние сразу после `toggleMuteAudio()`
- `onPeerJoined` (только в `GroupCallUI.tsx`, `CallUI.tsx` — звонок 1-на-1, там участник всего один и этот кейс не нужен) → повторно отправить состояние из `isMutedRef` (ref, чтобы избежать stale closure в колбэке `groupCallService.init`)

### Клиент — состояние

- `GroupCallUI.tsx`: `remoteMicMuted: Map<string, boolean>` — по умолчанию участника нет в карте → трактуется как «не замьючен» (до получения первого события; окно закрывается быстро за счёт немедленной отправки при входе)
- `CallUI.tsx`: `remoteMicMuted: boolean` — участник один, карта не нужна
- Слушатели `wsService.on('mic_muted' | 'mic_unmuted', ...)`, фильтруются по тому, что `user_id` — участник текущего звонка (по аналогии с уже существующим фильтром для `screen_share_started`)
- Очистка карты вместе с остальным call-state в `onCallEnded`/`onError`/`onReconnecting` (там же, где сейчас `setParticipants([])`, `setScreenSharers(new Set())`)

### Индикация говорящего — переиспользование `useMicLevel`

Хук уже существует и ничего не меняет в сигнатуре — просто вызывается для `p.stream` каждого участника вместо `groupCallService.localStreamState`.

Хуки нельзя вызывать внутри `.map()`, поэтому для группового звонка выделяется подкомпонент `RemoteParticipantTile`, инкапсулирующий вызов `useMicLevel(p.stream, remoteMicMuted.get(p.userId) ?? false)` и рендер плитки. Используется в обоих местах, где сейчас руками дублируется рендер participant-плитки: в `video-grid` (обычная сетка) и в `screen-share-thumbnails` (полоска миниатюр при фокусе на шаринге экрана) — параметр `layout: 'grid' | 'thumbnail'` переключает разметку, вызов хука и бейдж общие.

Для `CallUI.tsx` (1-на-1) подкомпонент не нужен — участник один, хук вызывается прямо в теле компонента: `useMicLevel(remoteStream, remoteMicMuted)`.

### Визуальный компонент — бейдж-индикатор (кружок в углу плитки)

Выбран пользователем по мокапам (вариант C из трёх показанных): постоянный кружок 26px в нижнем правом углу плитки (не пересекается с `.focus-btn` в верхнем правом), 3 состояния:

| Состояние | Приоритет | Вид | Иконка |
|---|---|---|---|
| `muted` | 1 (наивысший) | красный кружок | 🔇 (переиспользует эмодзи из кнопки управления мьютом — не 🚫, тот уже означает «микрофон недоступен») |
| `unmuted && level > 0.05` | 2 | зелёный кружок, pulse-анимация | 🎤 |
| `unmuted && level ≤ 0.05` | 3 (по умолчанию) | серый кружок | 🎤 |

Мьют проверяется явным булевым флагом, а не косвенно через нулевой уровень VAD (хотя технически замьюченный трек и так даёт ~0 — `useMicLevel` уже получает `isMuted` вторым аргументом и обнуляет level).

Дополнительно, при `unmuted && level > 0.05`, рамка всей плитки подсвечивается — переиспользуется существующий класс `.video-tile.speaking` (зелёная рамка + glow), добавляется аналог `.thumbnail-tile.speaking` для полоски миниатюр (сейчас такого класса нет).

**Унификация со своей плиткой:** существующий инлайновый `mic-dot` (мигающая точка перед именем в лейбле) заменяется тем же бейджем-кружком — состояние `muted` берётся из локального `isMuted` без WS round-trip, `speaking` — из уже существующего `micLevel`. Это даёт одинаковый визуальный язык для всех плиток в звонке, своей и чужих.

### CSS — новые/изменённые классы

- `client/src/components/GroupCallUI.css`: `.mic-badge` (база: position absolute, bottom-right, круг), `.mic-badge--muted`, `.mic-badge--speaking` (+ `@keyframes` pulse), `.mic-badge--idle`; `.thumbnail-tile.speaking` (аналог `.video-tile.speaking`, меньшая тень под размер миниатюры)
- `client/src/components/CallUI.css`: те же модификаторы `.mic-badge`, применяются к `.remote-video` и `.local-video`

## Edge cases

- Участник заходит в звонок, где кто-то уже замьючен/говорит — закрывается повторной отправкой состояния на `onPeerJoined` (см. поток данных выше); окно рассинхронизации — от момента SFU-join до получения WS-broadcast, в худшем случае доли секунды
- Реконнект — не требует отдельной обработки (см. выше), состояние подтягивается через `onPeerJoined` у остальных участников
- Микрофон недоступен физически (`isMicAvailable === false`) — трактуется как `muted`, бейдж красный, WS-событие `mic_muted` отправляется как обычно
- Участник вышел из звонка — запись в `remoteMicMuted` удаляется вместе с самим участником из `participants` (не обязательно явно чистить карту — рендерится только для существующих `participants`, мёртвые записи в `Map` не рендерятся и не текут по памяти между звонками, т.к. вся карта сбрасывается в `onCallEnded`)
- `level` мигает у порога 0.05 при тихой речи — уже существующее поведение локального индикатора, не новая проблема этой фичи

## Тестирование

- Серверный обработчик — чистый broadcast без состояния, как `screen_share_started/stopped`, у которого тестов в проекте нет; по аналогии тесты не заводятся (в отличие от VYC-34, где тестировалось нетривиальное состояние хаба — ростер с идемпотентностью)
- Ручной QA (2+ браузерные сессии): мьют/анмьют отражается у собеседника с задержкой в пределах WS round-trip; говорение подсвечивает правильную плитку среди нескольких участников; новый участник видит корректный мьют-статус уже присутствующих; поведение идентично в групповом и 1-на-1 звонке

## Вне скоупа

- Индикация уровня громкости (только бинарное «говорит / не говорит», не шкала)
- Push-to-talk и управление громкостью отдельных участников — отдельные пункты борды
- Серверный VAD / RTP-level индикация (обсуждалось на борде как альтернатива клиентскому VAD) — клиентский AnalyserNode уже проверенное решение в проекте, менять источник данных не требуется
