# Управление громкостью для каждого участника группового звонка

**Задача:** На карточке каждого собеседника в групповом звонке добавить кнопку "три точки", по нажатию на которую открывается поповер с регулировкой громкости (0–100%) конкретно этого участника — только для себя, локально, без сохранения между звонками.

**Дата:** 2026-07-20
**Ветка:** `VYC-40-participant-volume-control` (планируется)

## Проблема

Сейчас на плитке участника (`RemoteParticipantTile` в `GroupCallUI.tsx`) нет способа изменить громкость отдельного собеседника — только общий звук системы или полный мьют самого себя. Если один участник говорит громче/тише остальных, выровнять баланс нельзя.

## Решение

Звук удалённого участника сейчас воспроизводится через `<video>`-элемент, в который присваивается `srcObject = remoteStream` (аудио- и видеотреки идут вместе, см. `attachStreamToElement()` в `GroupCallUI.tsx`). У `HTMLMediaElement` есть нативное свойство `.volume` (0.0–1.0) — этого достаточно для диапазона 0–100%, отдельный граф Web Audio (`AudioContext`/`GainNode`) не нужен.

Настройка громкости:
- применяется только к текущему пользователю (не передаётся другим участникам и не сохраняется на сервере);
- не персистится между звонками (сбрасывается при каждом новом звонке — состояние живёт в памяти компонента `GroupCallUI`, не в `localStorage`);
- диапазон 0–100%, дефолт 100% (без изменений).

### Компоненты

**Новый компонент** `VolumeControlPopover.tsx` (+ `.css`) в `client/src/components/`:

```tsx
interface VolumeControlPopoverProps {
  value: number;             // 0-100
  onChange: (value: number) => void;
  onClose: () => void;
}
```

- `<input type="range" min={0} max={100}>` + текст с текущим значением в процентах.
- Закрывается по клику вне поповера (`mousedown`-листенер на `document`) и по `Escape`.
- Позиционируется относительно кнопки-триггера (CSS `position: absolute`, привязка к родителю — кнопка оборачивается в `position: relative` контейнер).

**Изменения в `RemoteParticipantTile`** (`GroupCallUI.tsx`):
- Новая кнопка "три точки" (SVG-иконка), всегда видима, в углу карточки — как существующие бейджи микрофона/шаринга. Не рендерится для локальной (своей) плитки — регулировать нечего.
- Локальное состояние `isVolumePopoverOpen` — своё для каждого тайла.
- Новые пропсы: `volume: number`, `onVolumeChange: (userId: string, volume: number) => void`.
- При клике на кнопку — открытие `VolumeControlPopover`; открытие нового поповера должно закрывать ранее открытый (одновременно виден только один).

На `thumbnail`-плитках (полоска миниатюр при фокусе на шаринге экрана) кнопка тоже показывается, уменьшенного размера, чтобы не перекрывать видео и не конфликтовать с `.focus-btn`.

### Данные и состояние

В `GroupCallUI`:

- `participantVolumes: Record<string, number>` — userId → 0–100, инициализируется `{}`.
- `getVolume(userId) => participantVolumes[userId] ?? 100` — дефолт 100%, если участника ещё не трогали.
- `handleVolumeChange(userId, value)`:
  1. обновляет `participantVolumes`;
  2. выставляет `volume = value / 100` напрямую на соответствующем `<video>`-элементе через уже существующую карту рефов (используется тот же механизм, что и в `videoRefSetter`/`attachStreamToElement`).
- Значение из `participantVolumes` применяется к `<video>.volume` каждый раз, когда поток (пере)подключается к элементу (в `attachStreamToElement`) — на случай, если у участника временно нет `stream` (видео/аудио выключено), а потом появляется: громкость должна восстановиться, а не сброситься к 100%.
- Отдельная очистка карты по выходу участника не нужна — вся карта сбрасывается вместе с остальным call-state при завершении звонка (`onCallEnded`/`onError`), как `participants`/`screenSharers`.

## Edge cases

- У участника нет `stream` (камера/поток выключены) — кнопка и слайдер доступны, значение из `participantVolumes` применится, как только поток подключится к `<video>`.
- Открыт поповер одного участника, пользователь кликает "три точки" у другого — первый поповер закрывается автоматически.
- Участник выходит из звонка, пока открыт его поповер — поповер закрывается вместе с исчезновением плитки (не рендерится отдельно от тайла).
- Новый звонок после предыдущего — `participantVolumes` создаётся заново пустым, все участники стартуют со 100%.

## Тестирование

Изменение чисто клиентское, без сетевого протокола и серверной логики — юнит-тестов не заводится (по аналогии с остальным UI звонка в проекте, тестов на нём нет).

Ручной QA (2+ браузерные сессии в групповом звонке):
- слайдер меняет громкость плавно без заикания звука;
- у разных участников можно выставить разную громкость одновременно;
- открытие поповера другого участника закрывает предыдущий;
- громкость сохраняется, если у участника временно пропадает и возвращается видео/аудио поток;
- при выходе из звонка и новом заходе громкость участников снова 100%;
- поведение идентично в grid- и thumbnail-раскладке.

## Вне скоупа

- Синхронизация громкости между устройствами пользователя или между участниками звонка — настройка сугубо локальная.
- Персист в `localStorage` между звонками — по решению пользователя, каждый звонок стартует с чистого листа.
- Буст громкости выше 100% (Web Audio/`GainNode`) — не требуется для текущего диапазона 0–100%, при появлении такого требования потребуется отдельный редизайн аудио-цепочки приёма.
- Регулировка громкости в 1-на-1 звонке (`CallUI.tsx`) — задача только про групповой звонок.
