# VYC-36 — Quotes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let a message that starts with `"> "` render as a quote block (left border + muted text) in the chat, and add a toggle button above the compose input that inserts/removes that `"> "` marker.

**Architecture:** Purely client-side, single component. `ChatArea.tsx` gains a `QUOTE_PREFIX` constant and a `renderMessageBody` wrapper around the existing `renderMessageContent` that detects the prefix and wraps the rendered output in a styled `<span>`. The compose input area is restructured from a bare `<form className="chat-input">` into `<div className="chat-input"><div className="chat-input-toolbar">…</div><form>…</form></div>`, which also activates an already-present-but-dead CSS rule (`.chat-input form { position: relative; }`) that keeps the mention dropdown anchored exactly where it is today.

**Tech Stack:** React + TypeScript (existing `ChatArea.tsx`/`ChatArea.css`), no new dependencies.

## Global Constraints

- Spec: `docs/superpowers/specs/2026-07-18-quotes-design.md` — every requirement below traces back to it.
- No new dependencies (npm) — everything is buildable with what's already imported in `ChatArea.tsx`.
- No backend changes: no migration, no `domain.Message` field, no API/WS payload change. If a task appears to need one, stop — that means a requirement was misread.
- Quote marker is exactly `"> "` (`>` followed by one space). `">text"` without the space is not a quote.
- UI copy in this file is already Russian (`Удалить сообщение?`, `(изменено)`) — the new button label `"Цитата"` matches that existing convention; do not translate to English.
- Client has **no unit test runner** configured (no vitest/jest in `client/package.json`, no `*.test.*`/`*.spec.*` files anywhere in `client/`). Every task here is verified via `cd client && npm run build:vite` (tsc type-check + build) plus manual browser/Electron QA — not automated tests.
- Follow existing icon convention in this file: inline `<svg xmlns="http://www.w3.org/2000/svg" width="14" height="14" viewBox="0 0 24 24" fill="none" stroke="currentColor" strokeWidth="2" strokeLinecap="round" strokeLinejoin="round">` (see the edit/delete buttons at `ChatArea.tsx:376` and `:384`).

## Task 1: Render `"> "`-prefixed messages as a quote block

**Files:**
- Modify: `client/src/components/ChatArea.tsx`
- Modify: `client/src/components/ChatArea.css`

**Interfaces:**
- Produces: module-level `const QUOTE_PREFIX = '> '` and function `renderMessageBody(content: string, members: MemberWithUser[], currentUserId?: string): React.ReactNode` — consumed by Task 2 (the toggle button reads `QUOTE_PREFIX` to decide its active state and to build the new input value).

This task is independently testable: `"> "` is a normal, already-typable string in the existing plain `<input type="text">`, so the button from Task 2 is not required to verify this task.

- [ ] **Step 1: Add `QUOTE_PREFIX` and `renderMessageBody`**

In `client/src/components/ChatArea.tsx`, insert immediately before the existing `function renderMessageContent(...)` (currently at line 20):

```tsx
const QUOTE_PREFIX = '> ';

```

Then insert a new function immediately after the closing brace of `renderMessageContent` (currently line 47, right before `export function ChatArea(...)`):

```tsx

function renderMessageBody(content: string, members: MemberWithUser[], currentUserId?: string) {
  if (!content.startsWith(QUOTE_PREFIX)) {
    return renderMessageContent(content, members, currentUserId);
  }
  const body = content.slice(QUOTE_PREFIX.length);
  return <span className="message-quote">{renderMessageContent(body, members, currentUserId)}</span>;
}
```

- [ ] **Step 2: Use `renderMessageBody` when rendering a message**

In `client/src/components/ChatArea.tsx`, find this line (currently line 360):

```tsx

```

Replace it with:

```tsx
                      <p className="message-text">{renderMessageBody(msg.content, members, user?.id)}</p>
```

- [ ] **Step 5: Manual verification**

- Send `> hello world` — confirm it renders as a quote: left border, indented, muted/greyish text, and the literal `"> "` is NOT shown (only `hello world` is visible).
- Send `>hello` (no space after `>`) — confirm it renders as a **plain** message, literal `>hello` text, no quote styling (this confirms the exact-prefix rule from the spec).
- Send `> @yourusername hello` (mention your own username) — confirm the `@username` mention is still highlighted (pill/color) *inside* the quote block.

- [ ] **Step 1: Add the toggle handler**

In `client/src/components/ChatArea.tsx`, find the end of `handleSubmit` (currently lines 159–172):

```tsx
  const handleSubmit = async (e: FormEvent) => {
    e.preventDefault();
    if (!channel || !input.trim() || !user) return;

    try {
      const msg = await apiService.createMessage(channel.id, input.trim()) as Message;
      addMessage(msg);
      setInput('');
    } catch (err) {
      console.error('Failed to send message:', err);
      setSendError(err instanceof Error ? err.message : 'Failed to send message');
      setTimeout(() => setSendError(null), 5000);
    }
  };
```

Immediately after that closing `};`, insert:

```tsx

  const toggleQuotePrefix = () => {
    setInput((prev) => (prev.startsWith(QUOTE_PREFIX) ? prev.slice(QUOTE_PREFIX.length) : `${QUOTE_PREFIX}${prev}`));
    requestAnimationFrame(() => inputRef.current?.focus());
  };
```
