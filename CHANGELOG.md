# Changelog

## v1.8.0 - 2026-08-19

### Новые возможности

#### Объединение текстовых и голосовых каналов (VYC-77)
- Каналы больше не делятся на текстовые и голосовые: в каждом канале есть и чат, и голос.
- Вход в голос — по кнопке (в строке канала и в шапке чата), а не по открытию канала.
- Звонок не зависит от навигации: можно уйти в другой канал или сервер, не покидая звонок; внизу
  сайдбара плашка управления.
- В канале звонка — сплит: сцена сверху, полноценный чат снизу (встроенный урезанный чат удалён).
- Кнопка входа в голос в строке канала сделана явной: раньше это было эмодзи с `opacity: 0`,
  проявлявшееся только при наведении, — то есть на тач-устройствах кнопки не существовало вовсе.
  Теперь иконка видна всегда, при наведении на канал раскрывается в зелёную кнопку
  «Подключиться», есть состояния нажатия и фокуса с клавиатуры; на тач-устройствах кнопка
  раскрыта сразу.
- Миграция 017 удаляет колонку `channels.type`. Откат необратим по данным — перед прод-миграцией
  снять `pg_dump` таблицы `channels`.

## v1.7.5 - 2026-08-18

### Новые возможности

#### Устойчивость голосовых звонков к обрывам сети (VYC-78)
- **ICE restart вместо полного реджойна при потере медиа-пути.** SFU сам
  пересобирает ICE (`negotiator.go`, offer с `ICERestart: true`) по своему
  таймеру `disconnected` или по запросу клиента (`request_ice_restart`).
  Клиентская «лестница восстановления» (`connectionRecovery.ts`) сначала даёт
  соединению 2 секунды на самовосстановление, затем просит рестарт и ждёт
  ещё 8 секунд, и только потом идёт на полный реджойн — раньше единственной
  реакцией на любой сетевой сбой был разрыв WebSocket и пересборка
  PeerConnection с нуля, с ренеготиацией у всех остальных участников комнаты.
- **Grace-сессия: обрыв сигнального WebSocket больше не значит выход из
  комнаты.** Участник остаётся в звонке — PeerConnection жив, треки
  продолжают форвардиться — до 15 секунд, ожидая переподключения по
  резюме-токену, выданному при входе. При успешном resume сервер подменяет
  сигнальную сессию на уже существующем участнике, без пересоздания
  PeerConnection и без ренеготиации у остальных. Клиент при обрыве
  собственного WS сначала пробует resume (новый WebSocket, тот же
  PeerConnection) и только при неудаче откатывается на полный реджойн.
  Событие `resumed` довозит участнику список собравшихся и активных
  демонстраций экрана, пропущенный, пока сессия была в grace — иначе
  события о чужих входах/выходах, случившиеся в этот момент, терялись бы
  безвозвратно (доставлять их дальше некому).
- **Presence через SFU.** Список «кто в звонке» в сайдбаре раньше держался
  только на клиентских событиях `voice_joined`/`voice_left` — моргнувший
  WebSocket вычищал участника у всех, хотя сам звонок продолжался. Теперь
  API раз в 5 секунд сверяет список с фактическим состоянием SFU
  (`GET /presence`, новый эндпоинт) и молча поправляет расхождения,
  рассылая обновление только по изменившимся каналам; `voice_joined`/
  `voice_left` остаются быстрым оптимистичным путём. `/stats` и `/presence`
  на SFU закрыты общим внутренним секретом (`SFU_INTERNAL_SECRET`) — `/stats`
  ранее был открыт в интернет без какой-либо авторизации.
- **Экспоненциальный backoff клиентского WebSocket.** Переподключение после
  обрыва (`websocket.ts`) больше не бьёт в сервер с фиксированным интервалом
  3 секунды — full jitter с растущим потолком, чтобы после падения сервера
  все клиенты не долбили его синхронной пачкой запросов на одном и том же
  ритме.

#### Диагностика пауз рантайма SFU (VYC-76)
- Watchdog (`internal/sfu/diagnostics`) — горутина с тикером на 20 мс,
  замечающая собственное опоздание: если процесс не был вызван планировщиком
  дольше 200 мс, в лог летит `runtime stall detected` (признак паузы GC,
  вытеснения ОС или майнор-page-fault на свопе). Ноль аллокаций на быстром
  пути.
- `deploy/vyc76-report.sh` получил секцию, сопоставляющую моменты
  `runtime stall` в логах SFU с зафиксированными на клиенте эпизодами
  ускорения речи (`inbound-accel`) в окне ±5 секунд — первая проверка,
  способная напрямую подтвердить или опровергнуть гипотезу «дело в паузах
  самого SFU-процесса», как только повторится живой эпизод.

### Инфраструктура
- `docker-compose.prod.yml`: `api` получил `extra_hosts:
  host.docker.internal:host-gateway` — `sfu` работает в `network_mode: host`
  (без него ICE по UDP не работает через докеровский NAT) и поэтому не имеет
  адреса в bridge-сети, где живёт `api`; без этой записи воркер сверки
  presence не может достучаться до SFU по имени.
- `.env.example`/`.env.prod.example` документируют `SFU_INTERNAL_SECRET` и
  `SFU_INTERNAL_URL`.

## v1.7.3 - 2026-08-14

### Исправления

#### Авторизация не проходила в собранном приложении (VYC-75)
- Причина: Electron грузит прод-сборку через `loadFile(...)` ("file://"),
  поэтому браузер отправляет запросы к API с заголовком `Origin: null`.
  Серверный CORS-мидлварь (`cors.go`) разрешал только dev-адреса и
  `CLIENT_URL` веб-версии origin `null` в списке никогда не было, поэтому
  сервер не выставлял `Access-Control-Allow-Origin`, браузер блокировал
  ответ, и все fetch-запросы при старте (`auth/me`, `auth/refresh`,
  `servers`, `users/online`) падали с `TypeError: Failed to fetch`
  (GlitchTip issue #38). Баг не был специфичен для Linux та же ошибка
  воспроизводилась на Windows и macOS начиная с v1.6.0.
- В `AllowedOrigins` (`DefaultCORS()`) добавлен `"null"`.

## v1.7.2 - 2026-08-13

### Исправления

#### Шумные ошибки в GlitchTip (VYC-74)
- `ChatArea.tsx`: удаление уже удалённого сообщения (гонка между вкладками/
  устройствами, либо собственное WS-событие удаления ещё не дошло до этого
  клиента) больше не логируется как ошибка — конечное состояние и так
  совпадает с ожидаемым, сообщение просто убирается локально.
- `GroupCallUI.tsx`: отмена системного пикера демонстрации экрана
  (`NotAllowedError`) больше не считается сбоем — раньше на каждый закрытый
  без выбора пикер летели `alert` и репорт в GlitchTip.
- `groupCall.ts`: добавлен счётчик `sessionEpoch`, помечающий текущий
  цикл join/reconnect. Устаревший цикл `reconnect()`, запущенный до свежего
  join/rejoin, теперь замечает, что его обогнали, и не открывает второе
  WebSocket-соединение — раньше оно могло достроиться позже, подменить
  `this.ws` и выстрелить ложным `onError` в уже здоровый звонок.

#### Аватарки и стикеры пропадали при каждом ребилде
- Причина: `UPLOAD_DIR` (`/var/lib/vycord/uploads`) не был примонтирован с
  хоста в контейнер `api` — загруженные файлы жили только в writable-слое
  контейнера и терялись при каждом `docker compose up -d --build`, хотя
  записи о них оставались в БД (битые иконки/стикеры после деплоя).
- В `docker-compose.prod.yml` добавлен bind-mount `/var/lib/vycord/uploads`
  для сервиса `api`, по аналогии с уже существующим для `coturn`.
- `deploy/deploy.sh` теперь создаёт каталог на хосте (`mkdir -p`) перед
  запуском контейнеров, чтобы права были предсказуемыми.

## v1.7.1 - 2026-08-12

### Исправления

#### Диагностика ошибок WebSocket (VYC-73)
- `toError` в `logger.ts` больше не превращает DOM `Event`/`CloseEvent` в
  бесполезную строку `[object Event]` (GlitchTip issue #11) извлекается

  `GET /api/v1/users/{id}` в проде это заканчивалось
  `TypeError: Failed to fetch` из-за лимита соединений браузера.

## v1.7.0 - 2026-08-12

### Новые возможности

#### Ротация refresh-токенов (VYC-72)
- Внедрён полный жизненный цикл токенов: клиентский `accessToken`/`refreshToken` с поддержкой ротации.
- Токен доступа теперь живёт 15 минут и обновляется в фоне; добавлены маршруты `/auth/refresh` и `/auth/logout`.
- Структура хранилища: доменный тип, репозиторий PostgreSQL и миграция `016_refresh_tokens` (таблица refresh-токенов).
- Продлевающие refresh-токены генерируются и хэшируются в `pkg/authtoken`; старые ротационно инвалидируются.
- Обнаружение повторного использования (reuse detection): подозрительная активность отзывается.
- Грация при ротации: разумный запас, чтобы потерянный ответ на refresh не отзывал сессию спонтанно.
- Автообновление без дедупликации параллельных запросов и проактивное планирование обновления.
- Повторная попытка запроса после тихого refresh на 401 в `api.ts`.
- Синхронизация состояния авторизации и WS-токена между вкладками; обработка по видимости вкладки (`pagevisibility`).
- Интеграция нового жизненного цикла токенов в логин, регистрацию и начальную загрузку приложения.

### Исправления
- `MarkRotated` возвращает `ErrRefreshTokenNotFound` при нуле изменённых строк.
- Таймер обновления запускается и для уже действующих токенов.
- Требуется «живой» следующий refresh-токен перед предоставлением окна грации.
- Убран жёсткий навигационный переход, ломавший работу в Electron, в пользу тихого ретрая.

## v1.6.1 - 2026-08-11

### Исправления

#### Сборка релиза (VYC-71)
- Исправлена ошибка компиляции TypeScript (TS2367) в `client/electron/main.ts`,
  из-за которой `npm run build` падал на всех ОС в GitHub Actions и релизы
  не публиковались (в артефактах отсутствовал `latest-linux.yml`, из-за чего

  ложным. Исправлено аннотацией типа `: string` в `client/electron/sentry-config.ts`.

#### Отчёт об ошибках на клиенте (VYC-43)

- Единый `logger.error`, маршрутизирующий консольные ошибки компонентов и сервисов в Sentry/GlitchTip.

- Инфраструктура: nginx-конфиг для `errors.vycord.webvaha.ru`, документация первичной настройки в README.

### Исправления

#### Звук больше не «ускоряется» в голосовых каналах (VYC-70)
- Развязали форвардинг RTP: у каждого подписчика своя очередь и своя горутина вместо общей `TrackLocalStaticRTP`.
- Общая запись раньше блокировала ридер публикующего участника: заблокированный подписчик накапливал пайон-буфер (до 1 МБ аудио), который затем раздавался всем слушателям разом — их NetEq сжимал задержку и выдавал ускоренный звук.
- Теперь запись не блокируется, ридер держится живого эфира, а отстающий подписчик тихо теряет пакеты из собственной очереди, не влияя на остальных.
- Очереди с границами: 50 пакетов (~1 сек) для аудио и ~250 пакетов для видео (ключевой кадр не рвётся посреди потока).
- Защита от регистрации sink'ов после закрытия сессии и от дублирующих sink'ов.
- Added e2e-проверку переключения аудио/реконнекта голоса `client/e2e/voice-reconnect-audio.html`.
